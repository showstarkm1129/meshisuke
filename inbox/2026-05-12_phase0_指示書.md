このフェーズでは **実際のアプリロジックは一切実装しない**。ツールチェーンとディレクトリ骨格の確立だけを行う。

## タスク詳細

### タスク 1: Vite + React + TypeScript プロジェクト初期化

**実行ディレクトリ**: リポジトリルート (`C:\Github\meshisuke`)

```powershell
npm create vite@latest app -- --template react-ts
cd app
npm install
```

- テンプレートは必ず `react-ts` を指定すること（`react` や `react-swc-ts` は不可）。
- `npm create vite@latest` で対話プロンプトが出た場合は、プロジェクト名に `app`、フレームワークに `React`、バリアントに `TypeScript` を選択する。
- 初期化後、`app/` 直下に以下が存在することを確認する:
  - `package.json`
  - `vite.config.ts`
  - `tsconfig.json` / `tsconfig.node.json`
  - `src/` ディレクトリ
  - `index.html`

---

### タスク 2: ESLint の追加設定

**前提**: Vite + React + TypeScript テンプレートは `@eslint/js` 等の基本設定を含む `eslint.config.js` を生成する（Vite 6 以降のデフォルト形式）。この形式を **そのまま採用し、書き換えない**。

**追加インストール**（`app/` ディレクトリ内で実行）:

```powershell
npm install --save-dev eslint-plugin-react-hooks eslint-plugin-react-refresh
```

- テンプレートがすでにこれらを含んでいる場合はインストール不要（`package.json` を確認してから判断する）。

**`eslint.config.js` への追記事項**（テンプレート生成内容に追記する形で対応）:

- `react-hooks/rules-of-hooks` を `error` に設定
- `react-hooks/exhaustive-deps` を `warn` に設定
- `react-refresh/only-export-components` を `warn` に設定（テンプレートに既存の場合は重複追加しない）

---

### タスク 3: Prettier の導入

**インストール**（`app/` ディレクトリ内で実行）:

```powershell
npm install --save-dev prettier eslint-config-prettier
```

**作成ファイル: `app/.prettierrc`**

```json
{
  "semi": true,
  "singleQuote": true,
  "tabWidth": 2,
  "trailingComma": "es5",
  "printWidth": 100,
  "endOfLine": "lf"
}
```

**作成ファイル: `app/.prettierignore`**

```
dist/
node_modules/
```

**`eslint.config.js` の末尾（または適切な位置）に `eslint-config-prettier` を追加**:
- Prettier との競合ルールを無効化するため、`eslint.config.js` の extends 相当の箇所に `eslint-config-prettier` を末尾で適用する。
- 具体的な記述形式は生成されたテンプレートの `eslint.config.js` の構造を読んで合わせること（flat config 形式の場合はオブジェクトとして spread する）。

### タスク 4: tsconfig の調整

Vite テンプレートが生成する `tsconfig.json` に対して、以下の項目を確認・追記する。
**既存の設定を削除しないこと。追記・変更のみ行う。**

`app/tsconfig.json` の `compilerOptions` に確認・追加:

```json
{
  "compilerOptions": {
    "strict": true,
    "noUnusedLocals": true,
    "noUnusedParameters": true,
    "noFallthroughCasesInSwitch": true,
    "exactOptionalPropertyTypes": false
  }
}
```

- `strict: true` はテンプレートにすでに含まれている場合がほとんど。重複記載は避け、ない場合のみ追加する。
- `exactOptionalPropertyTypes: false` はオプション。将来的に有効化を検討するが、MVP 開発中は外している（理由: 段階的に型を強化するため）。

### タスク 5: ディレクトリ骨格の作成

`app/src/` 配下に以下のディレクトリを作成する。各ディレクトリには `.gitkeep` ファイルを 1 つ置く（Git に空ディレクトリを記録するため）。

```
app/src/
├── components/     # UI コンポーネント（再利用可能なもの）
├── hooks/          # カスタム React フック
├── lib/            # ユーティリティ・ビジネスロジック（フレームワーク非依存）
├── providers/      # LLM プロバイダー実装・コンテキストプロバイダー
├── types/          # TypeScript 型定義（*.types.ts / *.d.ts）
└── pages/          # ページ単位のトップレベルコンポーネント（後のルーティング拡張を見越す）
```

- Vite テンプレートが生成する `src/App.tsx` / `src/main.tsx` / `src/assets/` / `src/index.css` / `src/App.css` は **削除しない**。そのまま残す。
- `src/components/` などのディレクトリは **新規追加** のみ行う。

## 実装時の注意事項

- **`app/` 外のファイルには一切手を触れない**（`システムプロンプト.md`、`data/`、`README.md`、`CLAUDE.md` 等はスコープ外）
- テンプレートが生成した既存ファイルの削除は原則禁止。変更が必要な場合は追記・上書きのみ行う
- `node_modules/` は `.gitignore` に含まれていることを確認する（Vite テンプレートは通常含んでいる）
- Windows 環境のため、`package.json` の scripts で POSIX シェル固有の記法（`&&` を除く）は避ける
