# 実装計画: API エラー緊急修正

**作成日**: 2026-05-27
**ステータス**: 着手中
**背景**: OpenRouter / Gemini Direct のどちらでも `sendUserMessage` が毎回エラー終了し、実験不能。
コードレビューで複数の論理バグを特定したため、緊急で修正する。

---

## スコープ（触るファイル）

| ファイル | 修正内容 |
|---|---|
| `app/src/hooks/useSettings.ts` | legacy モデルキーの provider 越境バグを修正 |
| `app/src/lib/tools.ts` | `type: ['number','null']` の OpenAI 非互換構文を除去 |
| `app/src/lib/llm/gemini.ts` | モデル名の `trim` + `encodeURIComponent` |
| `app/src/lib/llm/openrouter.ts` | `JSON.parse(tool.arguments)` の保護 |
| `app/src/hooks/useChat.ts` | 空入力 / isWaiting 連投ガード、id 衝突、APIキー欠落の無音失敗を解消 |

**触らない**: `data/*.json`、`types/data.types.ts`、外部送信先の追加・変更。
セマンティクス（`satisfaction: number | null`）はアプリ側の型を維持。

## 修正詳細

### 1. `useSettings.ts` — legacy モデル越境バグ

**症状**: provider を切替後の初回リクエストで別 provider のモデル名が送られて 400。

**修正**:
- `getModel` の `legacyModel` フォールバックを削除（provider 一致時のみ参照していたが、`setModel` が legacy キーも上書きしているため別 provider に漏れる）。
- `setModel` から `localStorage.setItem('meshisuke_active_model', model)` の legacy 書き込みを削除。
- 起動時 1 回だけ legacy → provider 別キーへマイグレーションし、legacy キーは削除。

### 2. `tools.ts` — `satisfaction` の型を OpenAI 互換に

**症状**: `type: ['number','null']` を許容しない OpenAI 互換実装（DeepSeek 等）で 400。

**修正**:
- `satisfaction` の型を `{ type: 'number', description: '1〜5。記録時に未確定なら省略可。' }` に変更。
- `record.required` から `'satisfaction'` を除外。
- アプリ側 `MealRecord.satisfaction` は `number | null` のままで、保存時に未設定なら `null` を補う方針（`appendMealRecord` 側でデフォルトを当てる）。

> Gemini 側は `convertSchema` で配列型を `nullable: true` に正規化していたので Gemini Direct では落ちないはずだが、required 配列にあると Gemini の strict validation が拒否する個体がある。両方解決する形に統一。

### 3. `gemini.ts` — URL に入るモデル名の正規化

**修正**:
- `const safeModel = encodeURIComponent(req.model.trim());`
- これを URL に埋め込む。

### 4. `openrouter.ts` — tool_calls 引数 JSON の防御

**修正**:
- `JSON.parse(tc.function.arguments)` を try/catch でラップ。失敗した tool_call はスキップして `console.warn` のみ（ユーザーには `Chat Error: SyntaxError` を見せない）。

### 5. `useChat.ts` — 入力/状態ガード

**修正**:
- `sendUserMessage` 冒頭に追加:
  - `if (isWaiting) return;`
  - `const trimmed = text.trim(); if (!trimmed) return;`
  - apiKey 欠落時は `dispatch ADD_ERROR` で可視化（無音 return をやめる）。
- `id: Date.now().toString()` を `generateId()` に置き換え、同一ミリ秒衝突を回避。

1. `npm run typecheck`（または `tsc --noEmit`）が通ること。
2. `npm run lint` が通ること。
3. 手動: Gemini で `gemini-2.5-flash` を選択 → 1往復成功 → OpenRouter に切替 → モデルを `deepseek/deepseek-chat` に → 1往復成功（**legacy 漏洩バグの再現条件確認**）。
4. 手動: 空入力 Enter で何も起きない / API 呼ばれない。
5. 手動: `add_meal_record` が呼ばれるシナリオで 400 が出ない。
