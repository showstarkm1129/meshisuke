---

## 1. 今回の作業範囲（スコープ）

「ブラウザだけで完結するローカル Web アプリ」の **MVP** を作る。
完成条件は以下 4 点をユーザーが実際に操作できる状態にすること。

1. ローカル PC の `data/` フォルダを開いて 4 ファイル（profile / equipment / pantry / meal_history）を読み込める
2. ユーザー自身の API キー（Claude または Gemini）で LLM を呼び出してチャットができる
3. 「システムプロンプト.md」の挙動でメシの提案・在庫更新を会話で行える
4. 「裏側モード」に切り替えると 4 ファイルの中身を JSON として閲覧できる（読み取り専用）

### スコープ外（MVP では実装しない）

- 初回フォームモードの専用 UI（チャット内構造化フォームは LLM 側に任せる）
- 裏側モードでの編集機能（閲覧のみ）
- 栄養データキャッシュ（MEXT 食品成分表 八訂）
- 作り置きの分割記録
- フォーム補完導線 UI
- API キーの暗号化（localStorage 平文で割り切り）
- File System Access API 非対応ブラウザでのフォールバック実装（案内表示のみ）
- OpenAI など Claude / Gemini 以外のプロバイダー

| 項目 | 決定内容 | 補足 |
|---|---|---|
| 進め方 | 構成.md 通り manager-agent 経由 | メインClaudeはマネージャー、実装は coding-agent、レビューは code-review-agent、説明は content-agent |

| 裏側モード | 読み取り専用の JSON 閲覧 | テーブル編集・JSON エディタは MVP 範囲外 |

## 3. フェーズ分割と作業項目

各フェーズ完了時に **code-review-agent → 必要なら修正計画 → coding-agent 修正** のサイクルを回す。
Phase 2 完了時には **security-check-agent**（API キー取り扱い）も実施する。

### Phase 0: プロジェクト基盤

- [ ] `app/` ディレクトリを作成し Vite + React + TypeScript テンプレートで初期化
- [ ] ESLint / Prettier / tsconfig の整備
- [ ] ディレクトリ規約の決定（components / hooks / lib / providers など）
- [ ] `app/README.md` に開発手順（`npm install` / `npm run dev`）を記載

### Phase 1: ローカルファイル I/O 層

- [ ] File System Access API でルートフォルダ選択 → `data/` 配下を検出
- [ ] 4 ファイル（profile.json / equipment.json / pantry.json / meal_history.jsonl）の読み込み
- [ ] ディレクトリハンドルのセッション中保持
- [ ] 保存モード（自動 / 手動）を設定で切替できる仕組み
- [ ] ファイル書き込みユーティリティ（JSON / JSONL 両対応）
- [ ] 読み込みエラー・スキーマ不整合時のハンドリング（最低限の通知）

### Phase 2: LLM プロバイダー抽象化

- [ ] `LLMProvider` インターフェース定義（`sendMessage`, `streamMessage` 等）
- [ ] Claude プロバイダー実装（Anthropic API）
- [ ] Gemini プロバイダー実装（Google Generative AI API）
- [ ] API キーを localStorage に保存・取得・削除する管理機能（プロバイダーごとに別キー）
- [ ] アクティブプロバイダーの設定切替
- [ ] `システムプロンプト.md` を system プロンプトとして送信、`data/*.json` を初回ユーザーメッセージに同梱
- [ ] **security-check-agent によるレビュー**

### Phase 3: チャット UI

- [ ] チャット画面レイアウト（メッセージ履歴 / 入力欄 / 送信）
- [ ] ユーザー / アシスタントメッセージの表示分け
- [ ] 応答中ローディング表示
- [ ] LLM 応答からの状態更新（在庫・履歴・嗜好など）反映ロジック
  - ※応答内の状態更新フォーマットはこのフェーズ着手前に再決定する（未確定事項参照）
- [ ] 自動保存モード時、状態変更を即座に `data/*.json` へ反映
- [ ] 手動保存モード時、変更バッファ + 保存ボタン

### Phase 4: 裏側モード（読み取り専用）

- [ ] モード切替トグル（ヘッダー or 設定）
- [ ] 4 ファイルの整形表示
- [ ] JSON シンタックスハイライト（軽量ライブラリ採用検討）

### Phase 5: 仕上げ

- [ ] File System Access API 非対応ブラウザの判定 + 案内表示
- [ ] API キー未設定時の導線
- [ ] フォルダ未選択時の導線
- [ ] エラー時のユーザー向けメッセージ整備
- [ ] 最終 code-review-agent によるレビュー
