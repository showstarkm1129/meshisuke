## 指示書から逸脱した判断

### 逸脱 1: `AppStateContext.tsx` の `Dispatch` インポート方法（軽微な修正）

**指示書の記述:** `type AppStateContextValue = { ...; dispatch: React.Dispatch<Action>; }`

**実際の実装:** `import { ..., type Dispatch } from 'react'` として `Dispatch<Action>` を使用。

**理由:** `tsconfig.app.json` に `verbatimModuleSyntax: true` が設定されているため、型専用のシンボルは `import type` または `import { ..., type Foo }` で参照しなければならない。`React.Dispatch` を使う場合は `import React from 'react'` が必要になるが、React 19 / react-jsx transform 環境では `React` を名前空間としてインポートする必要がなく、`noUnusedLocals` でエラーになる可能性がある。`Dispatch` を named import で直接取得する方が安全・シンプルなため変更した。

### 逸脱 2: `useFolderPicker.ts` の `SET_DIR_HANDLE` 二重 dispatch（指示書通りを維持）

指示書のコードには `dispatch({ type: 'SET_DIR_HANDLE', payload: rootHandle })` が 2 回記述されている（検証前に 1 回、全チェック通過後に 1 回）。論理的には冗長だが、指示書の記述通りに実装した（動作上の問題はない）。次フェーズ以降でリファクタリングを検討してよい。

## レビュー指摘 W-1/W-2 修正（2026-05-13 追記）

### 編集したファイル一覧

| ファイルパス | 変更内容 |
|---|---|
| `app/src/hooks/useFolderPicker.ts` | バリデーション前（旧 22 行目）の `dispatch({ type: 'SET_DIR_HANDLE', ... })` を削除 |
| `app/src/providers/AppStateContext.tsx` | `parseSaveMode` ヘルパー関数を追加し、`initialState.saveMode` の値を `parseSaveMode(...)` 呼び出しに置き換え |

### W-1 修正の要点

`useFolderPicker.ts` にあったバリデーション前の `SET_DIR_HANDLE` dispatch を削除した。これにより `data/` ディレクトリ存在確認・必須ファイル確認がすべて通過した後（旧 48 行目の dispatch）にのみ `state.dirHandle` がセットされるようになり、「バリデーション済みのハンドルのみが State に入る」設計に整合した。

### W-2 修正の要点

`AppStateContext.tsx` に `parseSaveMode(raw: string | null): SaveMode` ヘルパー関数を追加した。`'auto'` / `'manual'` の値のみを受け入れ、それ以外（不正文字列・`null`）はすべて `SaveModeConst.Auto` にフォールバックする。`initialState.saveMode` の `as SaveMode` キャストを `parseSaveMode(...)` 呼び出しに置き換えたことで、ローカルストレージに不正値が入っていても実行時に安全なフォールバックが働くようになった。
