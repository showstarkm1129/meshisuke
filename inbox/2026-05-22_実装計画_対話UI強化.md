---

## 0. 背景と目的

現状のチャット出力には 3 つの構造的な問題がある。

1. **Markdown が素のまま描画される**
   [MessageBubble.tsx:15](../app/src/components/MessageBubble.tsx#L15) が `{turn.text}` をそのまま挿入しているため、`**bold**` や箇条書きが文字通り表示される。
2. **冒頭サマリーの情報密度が高すぎる**
   システムプロンプト【継続モード】が「在庫ハイライト 3〜5 点」と書いているのに、実際は 10 品以上を中黒で連結して出力してしまう。一気に視覚情報が降ってくる。
3. **対話が「AI 主導の一方通行」になっている**
   ユーザーが操作で答えられず、毎回テキストを打たないと進まない。アプリ感が薄い。

本計画は **「描画レイヤーの底上げ」**＋**「プロンプト改修」**＋**「対話部品のリッチ化」** の 3 軸でこれを解決する。

---

## 1. 今回の作業範囲（スコープ）

### 完成条件

1. AI 出力の Markdown（太字・箇条書き・テーブル・GFM alert・`<details>`）がブラウザ上で正しく描画される
2. 継続モードの冒頭が「ヒント 1 行 + 質問 1 問」の形式になり、在庫の全列挙がなくなる
3. AI が選択肢を提示したとき、ユーザーがタップで返信できる（クイック返信チップ）
4. 食材列挙が pill 形 UI で描画される（`:::pantry` fence 経由）
5. 「おまかせ」ボタンが入力欄に常設される
6. AI が tool 呼び出し中（在庫照合・履歴確認）であることを進捗テキストで可視化する

### スコープ外（本計画では実装しない）

- 2 軸マトリクス UI（D4）— fence-to-component 機構が安定してから別計画で
- 期限近食材の「使う / 見送る」カード（D5）— 同上
- ステップインジケータ（D6）— 3 ターン以上のヒアリングが本当に発生するか検証してから
- 音声入力
- 食材アイコン辞書のフル整備（`name → emoji`）— Phase C で最小辞書（10〜20 個）のみ作り、必要に応じて拡張

### スコープ外にした理由

「過剰な抽象化・先回り実装をしない」原則（[CLAUDE.md](../CLAUDE.md)）に従い、**まず描画レイヤーと最も効くプロンプト改修だけ入れて効果を測る**。マトリクスや期限カードは fence パーサが安定し、実利用で必要性が確認できてから着手する。

### Phase A: 描画レイヤー基盤（最優先・工数小）

**ゴール**: 既存のシステムプロンプトが既に書いている Markdown 構造が、そのまま視覚的に伝わるようになる。

- [ ] `react-markdown` + `remark-gfm` + `rehype-raw` を `app/` に追加
- [ ] [MessageBubble.tsx](../app/src/components/MessageBubble.tsx) を `<ReactMarkdown>` に置き換え
- [ ] 許可 HTML タグを `<details>` `<summary>` のみに制限（`rehype-sanitize` のスキーマ拡張）
- [ ] GFM alert（`> [!warning]`, `> [!note]`）の色付き帯スタイルを `App.css` に追加
- [ ] バブル内の `max-width` / `line-height` を読みやすさ重視に調整
  （現状の `.message-bubble` を `max-width: 70ch; line-height: 1.7;` 程度に）
- [ ] 共通 fence パーサ `app/src/lib/fenceParser.ts` を新設
  - 入力: AI 出力テキスト
  - 出力: `{ kind: 'markdown' | 'pantry' | 'choices', payload }[]` の配列
  - `:::pantry` `:::choices` を抽出し、Markdown 本体と分離

**完了条件**:
- `**太字**` が太字描画される
- `> [!warning] 牛乳が明日まで` が色付き帯で表示される
- `<details>` が折りたたみ動作する
- fence パーサに `:::choices A|B|C :::` を渡すと `{ kind: 'choices', payload: ['A', 'B', 'C'] }` が返る

### Phase B: プロンプト改修（コード変更ゼロ・効果大）

**ゴール**: 出力構造を「ヒント1行 + 質問1問」に統一し、密度を下げる。

[システムプロンプト.md](システムプロンプト.md) の【継続モード】を以下に書き換える。

#### B-1. 継続モードの冒頭テンプレを差し替え

**Before（現状）**: 在庫サマリー 4〜5 行を一気に出力 → 質問。

**After**:
```
💡 ヒント: [期限近 / 直近傾向 / 在庫の偏り から 1 つだけ 1 行で]

こんにちは🍳 今日はどんな気分にしますか？

:::choices
さっぱり|がっつり|おまかせ
:::
```

- 在庫の全列挙は **しない**
- ヒントは 1 行・1 項目だけ
- 質問は必ず本文と空行 1 つ以上空けて末尾に配置
- 選択肢は `:::choices` fence で出す（Phase C で UI 化）

#### B-2. 「1 ターン 1 質問」を明文化

【継続モード】に以下を追記:
> **1 ターン 1 質問の原則**: ユーザーへの質問は 1 ターンに 1 つだけ。複合質問（「気分は？ あと時間は？」）を禁止。

#### B-3. 「文脈のチラ見せ」を定型化

ユーザーが気分を答えた次のターンで、AI は **裏で参照した情報を 1 行だけ** 添える。

```
なるほど、さっぱり系ですね 🍃
（期限近の牛乳は今日は使わない方向で考えますね）

具体的に提案する前に、調理時間 15 分以内 / 30 分以内 / 気にしない、どれにします？
```

→ プロンプトに「回答受領後の 1 行リアクション」のテンプレを追加。

#### B-4. favorites の即時参照

【継続モード】の冒頭処理に組み込む:
- `profile.favorites` に weight=3 がある場合、ヒント文 1 行を **「先週○○高評価でしたが、今日も寄せます？」** 形式にする
- weight=3 が複数あればランダム or 直近 `last_signal_at` 優先で 1 つ選ぶ

#### B-5. 連続パターンの自動検知

`meal_history` 直近 3〜5 件を見て、以下のいずれかに該当したら **AI から軌道修正を提案**：
- 3 日連続で主菜が同カテゴリ（肉 / 魚 / 麺 等）
- 3 日連続で同ジャンル（カレー / 中華 等）

提案フォーマット:
```
💡 3 日連続でお肉メインなので、今日は魚 or 野菜寄りで提案しようと思います。OK ですか？

:::choices
OK|肉でいい|おまかせ
:::
```

#### B-6. 質問末尾配置の徹底

【継続モード】【ルートA】【ルートB】すべてに「質問文は必ず本文と空行 1 つ以上空けて、最後に置く」を明記。

**完了条件**:
- 実利用 3〜5 ターンで「在庫の長文列挙」が出ない
- 1 ターンに質問が複数出ない
- favorites weight=3 がある場合、ヒント文に反映される

### Phase C: 入力リッチ化

**ゴール**: ユーザーがタップで返信でき、食材列挙が pill 形になる。

- [ ] `QuickReplyChips.tsx` を新設
  - 入力: `:::choices` fence の payload（文字列配列）
  - 表示: 入力欄の上、横並びのチップ
  - タップ: その文字列を `onSend` に流す → 自動送信
  - AI 返信受信時に消える
- [ ] `IngredientChips.tsx` を新設
  - 入力: `:::pantry` fence の payload
  - payload 形式: `[{"name": "玉ねぎ", "qty": "3個"}, ...]` または改行区切りの `玉ねぎ 3個`
  - 描画: `[🧅 玉ねぎ 3個]` のような pill を横並び（flex-wrap）
- [ ] `app/src/lib/ingredientEmoji.ts` を新設
  - 最小辞書（玉ねぎ・にんじん・じゃがいも・キャベツ・卵・鶏もも・牛乳・豆腐・納豆・米・うどん・ピーマン … 15〜20 種）
  - 未知の食材は `🥘` をフォールバック
- [ ] `MessageInput.tsx` に「おまかせ」ボタンを右側に常設
  - タップで `おまかせで` を送信
  - 入力中でも有効（disabled は LLM 応答待ち中のみ）
- [ ] [MessageBubble.tsx](../app/src/components/MessageBubble.tsx) を fence パーサ経由のレンダリングに切り替え
  - Markdown 部 → `<ReactMarkdown>`
  - `:::pantry` → `<IngredientChips>`
  - `:::choices` → メッセージバブル外（入力欄上）に hoist して `<QuickReplyChips>`

#### システムプロンプト追記

- `:::pantry` fence の出力ルールを追加（食材列挙をする場面では必ずこの fence を使う）
- `:::choices` fence の出力ルールを追加（2〜4 択を提示する場面では必ずこの fence を使う）

**完了条件**:
- AI が `:::choices さっぱり|がっつり|おまかせ :::` を返したら、入力欄上にチップが並ぶ
- タップで自動送信される
- `:::pantry` で渡された食材が絵文字付きの pill で描画される
- 「おまかせ」ボタンがどの状態でも入力欄右に見える

## 5. リスクと対処

| リスク | 対処 |
|---|---|
| `rehype-raw` で許可した HTML 経由の XSS | `rehype-sanitize` のスキーマで `<details>` `<summary>` のみホワイトリスト。`onclick` 等のイベント属性は全拒否 |
| fence パーサが Markdown の正規描画を壊す | `:::xxx` を fence として抽出後、残りはそのまま Markdown に流す。fence 内テキストは Markdown としてレンダリングしない |
| LLM が `:::choices` を毎回出してくれない | プロンプトに「選択肢を出すときは必ず `:::choices` fence を使う」を強制。出さなかった場合は通常テキストとして表示されるだけで壊れない（graceful degradation） |
| 食材絵文字辞書のメンテ負荷 | 未知食材は `🥘` フォールバック。完璧を目指さず、よく出る 15〜20 種だけ手で入れる |
| クイック返信チップがチャット履歴に表示されると古いものまでタップできてしまう | 最新の AI メッセージの `:::choices` のみ有効化。過去のメッセージのチップは表示しないか、disabled 表示にする |
| プロンプト改修だけで「在庫列挙」が止まらない可能性 | Phase B 実行後 3〜5 ターンで効果測定。止まらなければ「在庫列挙の禁止」を強い禁止語として明記し直す |
