# めし助 (Meshisuke) 🍳

> 一人暮らしの「今日のご飯どうしよ」を 30 秒で片付けるための、対話型・節約自炊アシスタント AI。

冷蔵庫の中身・嗜好・直近の食事履歴を踏まえて、今の気分に合う一品を提案します。
「アプリを操作している」感覚を壊さないために、ファイル名や JSON といった内部表現は通常会話では一切表に出しません。

---

## ✨ 何ができるか

- 在庫・期限・履歴を見て **今日の一品を即提案**（「カレー食べたい」「おまかせで」両対応）
- 不足食材があれば **代替案 or 買い足しリスト** の 2 択で確認
- アレルギーは復唱・絶対除外、嫌い物は **強度に応じて口調が変わる**（軽く確認 → 強く再考を促す）
- 調味料は **裏側で勝手に減らす**。ユーザーには「そろそろ無くなりそう」だけ知らせる
- 困ったときの **「裏側モード」** でデータを直接見たり編集したりできる（セーフティ）
- 仕上げに **栄養目安と一週間の傾向所見** を付ける

---

## 🧪 試し方（テスト段階）

現状はテストフェーズで、プロンプトとデータをチャット AI に貼って動かします。

1. [`システムプロンプト.md`](システムプロンプト.md) の中身を ChatGPT / Claude にコピー＆ペースト
2. 続けて [`data/`](data/) 配下の 4 ファイルの中身も同じチャットに貼る
3. 「今日のご飯どうしよ」と話しかける

> ⚠️ `data/` に入っているユーザー情報（嗜好・栄養目標など）は **仮想テストユーザーのサンプル** です。実在の個人データではありません。

## 🎯 完成形のビジョン

**ブラウザだけで完結するローカル Web アプリ** として実装予定。

- バックエンドサーバー無し（フロントエンドのみ）
- データはユーザー自身の PC 内に保存（File System Access API / localStorage）
- LLM 呼び出しは **ユーザー自身の API キー**（BYO Key）で行う
- 食生活データが第三者サーバーに送信されない設計

> プロンプト＋データという「ロジック層」を先に作り込んでから、その上に薄い UI を乗せていくアプローチ。プロンプト自体が仕様書を兼ねるイメージです。

## 🏗 設計のポイント

### 3 つの動作モード

| モード | 役割 |
|---|---|
| **初回フォームモード** | チャット内構造化フォームで初期データ収集。任意項目はスキップ可 |
| **継続モード** | 通常の会話。在庫サマリー → 提案 → 確定時に在庫更新 |
| **裏側モード** | 整形表＋生 JSON でデータを表示・編集できるセーフティ領域 |

通常会話では「JSON」「保存」などの実装語を出さない原則を守りつつ、**裏側モードだけ例外的に許可**。手詰まったらいつでもデータを直視できる安全弁を用意しています。

### 嗜好の重み付け

`favorites` / `dislikes` は単なる文字列リストではなく、構造化配列で扱います：

```json
{"name": "パクチー", "weight": 3, "last_signal_at": "2026-05-08", "signal_count": 4}
```

- `weight`: 1（軽度）／ 2（普通）／ 3（強度）
- 発話の強度（「めっちゃ好き」「あんまり」など）から重みが自動更新
- 嫌い物が候補に混入したとき、重みによって **AI の口調が3段階に変化**
  - 1: 「これ大丈夫でしたっけ？」
  - 2: 「これあんまりじゃなかった？ 今日はアリ？」
  - 3: 「嫌いだったので外したほうがいいのでは？」
- **weight=3 でも自動除外はしない**（最終判断はユーザー）。これがアレルギーとの根本的な違い

### 調味料の "意識させない" 管理

```json
{"name": "醤油", "amount_current": 250, "amount_full": 500, "unit": "ml"}
```

- レシピ確定時、AI が **推定ベースで雑に** 減算（大さじ1=15ml、味噌汁1杯≒味噌12g 等）
- 通常はユーザーに減算を告げない
- 残量比率が 20% / 10% / 0% に達したときだけ、さりげなく通知

### アレルギーの三値セマンティクス

`null` / `[]` / 値あり を厳密に区別：

| 値 | 意味 | 振る舞い |
|---|---|---|
| `null` | 未確認 | チャットで催促しない。会話で自発的に出てきたタイミングで確認 |
| `[]` | 確認済み・該当なし | フィルタは適用するが配列は空 |
| `["甲殻類"]` | 確認済み・該当あり | **絶対除外**（口調分岐の対象外） |

初回フォームでスキップされた項目を区別するために導入しています。

### 単位の正規化規約

- 重量は `g`、容量は `ml` の整数値に統一（kg / L は表示時のみ）
- 個数系は `個 / 本 / 玉 / 丁 / パック / 袋 / 枚 / 切れ` の限定セット
- 食材ごとに正規単位を1つ固定（例: 卵=`個`、牛乳=`ml`）
- 入力ゆらぎは AI が確認して正規化（「卵1パック買った」→「10個入りでしたか？」）

## 📂 リポジトリ構成

```
meshisuke/
├── システムプロンプト.md     # AI 人格・処理フロー・出力フォーマット（核となる仕様）
├── data/
│   ├── profile.json          # オンボーディング状態・嗜好（重み付き）・栄養目標
│   ├── equipment.json        # 調理器具（カテゴリ別）・スキル・制約
│   ├── pantry.json           # 食材在庫（storage enum）＋ 調味料残量
│   └── meal_history.jsonl    # 1 食 = 1 レコードの履歴
├── CLAUDE.md                 # 編集時の心構え（AI エージェント向け）
└── README.md                 # このファイル
```
